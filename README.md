# Документация проекта TrueLogs


## Суть
Опенсорс решение для просомтра и хранения логов.



## Философия
Цель получить простой легковесный инструмент для просмотра логов, требующий минимум усилий по настройке и администрированию.
Который можно развернуть за час и использовать на этап локальной разрабоки и тестовые стенды.
Проект не пытается быть супер быстрым и производительным, потому что задача пользователя не в этом, нужно быть простым и удобным при относительно небольшом обьеме данных.
Основным референсом является проект seq(https://datalust.co/) который устраивает всем кроме типа лицензии.
Философия близка к postman - инструмент утилита простой и удобный, разработчик переходит от одного проекта к другому используя один инструмент для разных проектов

## Режимы использования
- Локальный режим - по сути десктопное приложение, которое можно натравить на файл с логами и получить все удобства UI инструмента
- Серверный режим - замена SEQ

- Локальный режим: (NuGet Global Tool)
- Серверный режим: Linux (Docker)
- Локальный режим: Windows, Linux, macOS (native executable)


## Ограничения
Библиотеки для подключения пока только для .NET


## Как использовать

### TrueLogs как локальный инструмент просмотра логов из файлов
Запустить через NuGet Global Tool - ```dotnet tool install -g TrueLogs.Tool```
Или скачать native executable для вашей ОС и запустить.

### TrueLogs как сервис
Для централизованного сбора логов от нескольких сервисов
Запустить в Docker - ```docker run -p 5000:80 -v ./data:/app/data truelogs/server:latest```.
Пробросить наружу порт или использовать общую сеть.
Использовать api библиотеки что бы подключить логирование в TrueLogs.

## Архитектура

TrueLogs построена на принципе разделения ответственности:

1. **Ядро** (TrueLogs.Api.Host + TrueLogs.Storage) - хранение и доступ к логам
1. **Интерфейс** (TrueLogs.Web.Host) - взаимодействие с пользователем
1. **Клиенты** (TrueLogs.Client + Serilog.Sinks.TrueLogs и тд) - отправка логов
1. **Адаптеры** (TrueLogs.Adapter.File) - импорт логов из внешних источников
1. **Язык** (TrueLogs.TrueLang.File + TrueLogs.TrueLang.Translator.LiteDB и тд) - импорт логов из внешних источников

Это позволяет использовать систему в разных сценариях:
- Как локальный просмотрщик логов (native)
- Как централизованный сервер логов в облаке

## Требования для MVP

### MVP I Реализуем вариант локального развертыванипя с чтением лога из файла
- Поддерживает структурированные логи
- Предоставляет веб-интерфейс для просмотра логов, с возможностю фильтрации
- Простот настройки - натравить лог на файл, создать мапинг полей логоф из файла в TrueLogs, прописать в какую БД писать логи
- Простот развертывания - развернуть 1 контйенер, подключить 1 библиотеку, простое api

### MVP II Реализуем серверный режим
- Простота развертывания - развернуть контйенер, подключить библиотеку и получить UI с логами

## Стек для MVP

БД - LiteDB или PostgreSQL

Поставка MVP I - NuGet Global Tool

Поставка MVP II - Docker образ, библиотеки расширяющие стандартные инструменты, например Serilog Sink

## Примерная структура проектов в /src

### api/ - api бэкенда
- TrueLogs.Api.Host - ASP.NET Core приложение (API)

### aspire/ - локальное развертывание
- TrueLogs.Aspire.Host - развертыввание с помощью Aspire для локальной разработки

### contract/ - контракты
- TrueLogs.Contract.Web - контракт взаимодействия фронтенда и бэкенда, подключается обоими
- TrueLogs.Contract.Emitter - контракт взаимодействия источинка логов и бэкенда

### emitter/ - источники логов
- TrueLogs.Emitter.Client - клиент для отправки логов который использует api и контракт и который будут использовать клиенты и адаптеры

#### emitter/adapter -  адаптеры который работают с источниками
- TrueLogs.Emitter.Adapter.File - Адаптер для импорта файловых логов. Реализует фоновый watcher файловой системы. Отправляет логи в TrueLogs API через TrueLogs.Client

### emitter/integration - пакеты который можно подключить в свои проекты
#### emitter/integration/dotnet/ -  пакеты для популярных фреймворков логирования dotnet (Serilog, NLog, MEL)
- Serilog.Sinks.TrueLogs - Библиотека, NuGet пакет для экспорта из Serilog в TrueLogs

### lang/ - логика языка TrueLogs
- TrueLogs.TrueLang - Лексический и синтаксический анализ с формированием AST дерева
- TrueLogs.TrueLang.Translator.TrueLang - Транслятор AST дерева в TrueLang
- TrueLogs.TrueLang.Translator.LiteDB - Транслятор AST дерева в BsonExpression для LiteDB
- TrueLogs.TrueLang.Translator.PostgreSQL - Транслятор AST дерева в SQL для PostgreSQL

### storage/ - логика хранения логов
- TrueLogs.Storage - Библиотека, логика работы с хранилищем
- TrueLogs.Storage.LiteDB - Библиотека, реализация хранения данных в LiteDB
- TrueLogs.Storage.PostgreSQL - Библиотека, реализация хранения данных в PostgreSQL

### web/ - пользовательский UI
- TrueLogs.Web.Client - реализация контрактов из TrueLogs.Contract.Web которые подключает TrueLogs.Web.Host
- TrueLogs.Web.Host - Blazor UI, WebAssembly, MudBlazor 
- TrueLogs.Web.Store - Имплементация паттерна Flux для логики с использованием библиотеки Fluxor

## DSL - TrueLang

### Базовые правила

#### Идентификатор поля	
Начинается с @, затем буквы/цифры/подчёркивание (латиница). Регистр сохраняется.

Примеры: @level, @timestamp, @user_Id

#### Строковый литерал
Выделяются обратными кавычками `...`. Двойные и одинарные кавычки не используются. Экранирование пока не поддерживается.

Примеры: `Error`, `Hello world`

#### Числовой литерал
Целые или с плавающей точкой (разделитель – точка). Без кавычек.

Примеры: 42, 3.14

#### Литерал даты
Заключается в вертикальные черты |...|. Внутри — ISO-дата (формат yyyy-MM-ddTHH:mm:ss.fffZ).

Примеры:|2026-08-15T10:00:00Z|

#### Операторы сравнения	
=, >, <, >=, <=, ~ (последний означает «содержит подстроку»).	

Примеры: @level = `Error`, @count >= 5, @timestamp > |2026-08-15T10:00:00Z|

#### Логические операторы	
and, or, not — строго в нижнем регистре, регистрозависимые.

Примеры: @level = `Error` and not @level = `Warning`

#### Группировка	
Круглые скобки ( ).	

Примеры: (@level = `Error` or @level = `Warning`)

#### Пробелы
Игнорируются (кроме разделения токенов).

#### Приоритет операторов
not имеет самый высокий приоритет, затем and и or. 

and и or левоассоциативны, цепочки обрабатываются слева направо.

Рекомендуется использовать скобки для явного задания порядка, особенно в смешанных выражениях (например, (a or b) and c).rning')

#### Ошибки
При синтаксической ошибке возвращается понятное сообщение с указанием позиции.

### Примеры выражений
@level = `Error`

@timestamp > |2026-08-15T10:00:00Z|

@message ~ `exception`

@level = `Error` and @timestamp > |2026-08-15|

(@level = `Error` or @level = `Warning`) and @message ~ `timeout`

not @level = `Info`

@a = `1` and not @b = `2`

not (@level = `Error` or @level = `Warning`)

@level in [`Error`, `Warning`]
